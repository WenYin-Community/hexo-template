## 一、官方使用限制

**额度定义**：官方原文 "Usage limits are defined as monthly dollar amounts"，"Each model has the following usage limits: 5-hour — **20%** of the monthly limit; weekly — **50%**; and monthly — **100%**"。**Token pricing is the same for Go and Go Plus.**

| Go 月额度档 | 每 5 小时（20%） | 每周（50%） | 每月（100%） | 款数 |
|---|---|---|---|---|
| **$15** | $3 | $7.50 | $15 | 11 |
| **$20** | $4 | $10 | $20 | 1 |
| **$30** | $6 | $15 | $30 | 3 |
| **$60** | $12 | $30 | $60 | 10 |
| **$100** | $20 | $50 | $100 | 1 |
| **$500** | $100 | $250 | $500 | 1 |

- 🔑 **额度是"月度美元上限 + 比例窗口"**：窗口额度随模型档位自动按比例生成，不是各档独立的固定数字。**三档共用同一套比例**。
- **现行 6 档分布**：**$15（11 款，旗舰/新模型）**、**$20（1 款，`minimax-m3.1-flash`）**、**$30（3 款）**、**$60（10 款，成熟主力）**、**$100（1 款，`deepseek-v4.1-flash`）**、**$500（1 款，`glm-5.3` 促销值）**。
- ⚠️ **`glm-5.3` 的 $500 是促销值**：官方 docs 明示 "Higher usage limits apply through **November 22, 2026**"。其长期档位应按 **$15**（Plus $60，即 4x）理解——**11-23 起须重抓确认回落值**。**该值直接决定 Plus 的性价比结论，见第五节**。
- **为什么部分模型额度低**（官方 "Why some models have lower usage"）：多数模型靠**批量折扣 + 预留 GPU 容量**换取高月额度；新模型或公开价本身已打折的模型无折扣空间，**其额度只是"略高于直付厂商"**——这是档位差异的唯一解释，不是限速。
- **客户端要求**：① 发送典型 coding agent 流量；② **自带 user agent**（如 `my-coding-agent/1.0`），不要用通用 SDK/HTTP 库名；③ 每个会话发送稳定的 `x-opencode-session` 会话 ID。
  - **已验证客户端**：OpenCode、Hermes（含 PR #101864 的构建）、Claude Code、Codex、ZCode、Pi、jcode（v0.81.6+）、Kilo Code CLI（含 PR #13752，**不覆盖 VS Code 扩展**）。
  - **已知有问题**：DeepSeek Harness、GitHub Copilot Chat、Kimi Code、MiMo Code。
- **超额处理**：达月限额**不自动回落**，请求直接拒绝；可手动切免费模型，或开 **Extra Usage** 按量计费。响应头 `opencode.allowance` 回报本次请求计入额度的金额。
- **订阅范围**：**Go / Go Plus 仅限单成员 workspace**（带 Go 订阅的 workspace 无法邀请成员）；**Go Teams 为 $20/成员/月、2 成员起（最低 $40/月）**，第二席位覆盖下一个加入者免费，期中加入收 $20 获全额，服务账号不覆盖。三档均可用 workspace credit 支付订阅/续费/升级。
- **端点路径**：全部为 **`https://opencode.ai/inference/go/{openai,anthropic,google}/v1*`**，模型清单 `.../inference/go/v1/models`。旧 `zen/go/v1/*` 仍返 200 且 ID 一致（兼容别名），**新配置一律写新路径**。

## 二、三档额度与倍率（27 款付费模型全表，11-22 API 实测）

> 数据取自清单 API 的 **`go.monthly_usage.{go, go-plus, go-teams}`**，**三档一次给全**。**Plus 为乘数（2/3/4x），Teams 为加数（Go + $5）**——两种加成逻辑不同，**不可混用同一套倍数**。

| 档位 | 月费 / 人 | 与 Go 的关系 | 加成逻辑 | 单位价值（vs Go） |
|---|---|---|---|---|
| **Go** | **$10** | 基准 | — | **1.00x** |
| **Go Plus** | **$40** | **×2 / ×3 / ×4** | **乘数**（额度放大整倍） | **0.50x / 0.75x / 1.00x** |
| **Go Teams** | **$20** | **+$5** | **加数**（每模型加固定 $5） | **0.51x–0.67x**（随档位升高而下降） |

## 八、关键发现（现行结论）

1. **🔑 逐模型价目与请求数已完全公开，此前"不可获取"的判断被推翻**：清单 API 单次返回 `cost` / `go.monthly_usage` 三档 / `limit` / `capabilities`，**Console Go 页为公开页（HTTP 200，无需登录）**。**"需登录"是误判，已全库改正。**
2. **额度是"月度美元 + 比例窗口"**：5h = 20%、周 = 50%、月 = 100%，**窗口额度随档位自动按比例生成**。**所有付费模型共用一个额度池**——逐模型数字**不可相加**。
3. **🔑 Plus 上限就是 4x，且 4x 恰好是盈亏平衡点**：$10 → $40 是 4 倍价，**4x 持平、3x 贵 33%、2x 贵 100%**。**清单内没有 5x 及以上**——**Plus 最好只能"不亏"，不存在"更便宜"。**
4. **Teams 是加数不是乘数，且价格劣势随档位放大**：$15 档 +$5 → 1.33x 额度（单位价值 0.67x），$500 档 +$5 → 1.01x（0.51x）。**Teams 只能为"多成员独立额度 + 合规"买单。**
