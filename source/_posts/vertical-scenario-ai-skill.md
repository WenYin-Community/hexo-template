「笔记发出去没流量」是个被说烂的话题。与其再写一篇经验帖，不如做一个小工具：输入标题、正文、标签，直接给出评分、合规风险和改稿建议。

这次把它做成了一个能在两个 Skill 市场上架的完整作品。真正花时间的不是写代码，是**把「好笔记」拆成可打分的维度**，以及**让建议具体到能直接抄**。

<!-- more -->

## 一、先把交付物定死

工具类 Skill 最容易做成一堆模糊的「建议」。所以一开始就把输出限定为三块：

1. **五维评分**：标题点击力 25、开头钩子 20、种草密度 25、可信感 15、互动引导 15，满分 100；
2. **合规扫描**：极限词、医疗功效、诱导交易三类风险，逐条标出命中位置；
3. **改稿交付**：3 组备选标题、3 个开头首句、结构建议、3–10 个标签、发布前清单。

这三块必须同时存在——只评分不给改法，等于骂完人就走；只给改法不解释，用户不知道下次怎么自己判断。

## 二、评分要可解释，不能是玄学

每个维度都给明确的加减分项，而不是让模型「感觉一下」：

- **标题点击力**：具体数字、悬念缺口、人群指向、长度（20 字内）、有没有堆砌关键词；
- **开头钩子**：前两句有没有冲突/数字/反常识，有没有直接进入场景；
- **种草密度**：卖点是否可验证（用了多久、什么场景、前后对比），有没有空洞形容词；
- **可信感**：价格/渠道/身份是否交代，有没有「绝对」「第一」这类不可证实的表达；
- **互动引导**：结尾有没有具体问题或选择，而不是「欢迎点赞关注」。

实测校准：一个刻意写得「像广告」的样例得 72 分，按建议改稿后 94 分。**分数不是目的，差距能复现才有用**。

## 三、合规扫描：宁可误报，不可漏报

三类风险用词表 + 规则匹配：

- 极限词：「最」「第一」「顶级」「永久」等绝对化表达；
- 医疗功效：治疗、根治、消炎、减肥、降血压这类功效承诺；
- 诱导交易：私下交易、加微信、绕过平台下单。

规则匹配会误报（比如「最后一步」里的「最」），但在这个场景里**误报的代价远小于漏报**——用户看到高亮，自己判断要不要改。词表要能增量维护，别写死在代码里。

## 四、改稿要能直接抄

「建议标题更吸引人」这种话没有价值。交付物必须是可以直接替换的文本：

```text
标题备选（20 字内）：
1. 我用了 30 天，把笔记打开率从 3% 拉到 11%
2. 别再这样写开头了，平台真的不给流量
3. 同一条笔记改 3 个地方，播放量差 8 倍
```

首句同理——给出三个不同钩子类型（冲突型、数字型、场景型），让用户挑一个符合自己人设的。标签给 3–10 个，按「品类词 + 场景词 + 人群词」分组，而不是堆一堆大词。

## 五、零依赖，CLI 和 Agent 双用法

整个工具只用 Python 标准库：

- 命令行：`python -m note_doctor --title ... --body ...`，输出 Markdown 报告，非法输入退出码 2；
- Agent 用法：同一套评分函数包成 Skill，模型调用时返回结构化 JSON。

零依赖的好处是**分发简单**——一个 zip 解压即用，不需要用户装环境。包控制在 9 个文件、约 39KB，远低于平台的 40MB / 30 文件限制。

## 六、上架比开发麻烦

两个市场的上架流程都踩了坑：

- **小红书 Skill 市场**：CLI 发布连环失败——slug 超长、失败的提交会占用 Skill ID、编辑卡片又不改 frontmatter，换 ID 仍报「已被占用」。最后改 frontmatter 的 `name` 重打包、转网页端才成功；
- **华为云 Skill 市场**：页面里的上传控件在跨域 iframe 里，自动化驱动不了。改先把 Skill 推到公开代码仓，再在云端开发环境里 clone 后提交；两个 PR（技能文件 + 索引条目）等待合并；
- **浏览器自动化的边界**：附件上传被安全策略禁止（`Not allowed`），发布按钮在封闭 Shadow DOM 里点不到——最后一步只能人工完成。**把「能自动化的部分」和「必须人工的部分」分开，比硬啃更有进度**。

## 总结

做垂直场景的 Skill，经验可以压成三句：

- **交付物先定死**：评分、合规、改稿三件套，缺一块都不成立；
- **评分要可解释**：每个维度都有具体加减分项，改前改后能复现差距；
- **建议要能直接抄**：给可替换的标题、首句、标签，而不是「再优化一下」。

最后一句：**上架流程也是产品的一部分**。代码写完只是开始，能过审、能被搜到、能让人一键使用，才算做完。
