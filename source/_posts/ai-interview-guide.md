## 一、先看面试的评分骨架

整套题库共用同一个"五层"结构，这个顺序本身就是面试官的考察路径：

1. **基础认知（Why / What）**——岗位边界、概念分层、工程价值观
2. **核心技术能力（How）**——你能不能讲清机制，而不是背结论
3. **工程化与系统能力**——上线、监控、成本、兜底
4. **真实项目与业务场景**——你做过什么、你的角色、结果如何
5. **进阶与加分项**——架构判断、技术选型、未来视野

答题时把「是什么 → 为什么 → 工程上怎么落地 → 我实际怎么做的」四段走完，基本就不会失分。

## 二、岗位认知

- AI 应用开发 ≠ 调模型、写 Prompt，本质是**产品级 AI 能力的交付**。
- 四层结构要分清：模型与算法（能力来源）→ AI 应用（能力封装）→ AI 系统（权限、流程、日志、监控、兜底）→ 业务场景。
- 企业真正的瓶颈通常不在模型，而在应用设计：Prompt、上下文、数据、流程控制。
- "能上线"的标准不是效果好，而是：**可评估、成本可控、故障可兜底、有人能维护**。

## 三、Python

- 区分"脚本代码"与"工程代码"：边界清晰、异常有策略、配置不写死、可测试。
- 几个高频细节：生成器与惰性求值、深浅拷贝（AI 项目里真踩过）、可变/不可变对象、lambda 与推导式的可读性边界。
- 依赖与版本管理：锁版本、区分运行期与开发期依赖。
- 中大型项目的目录结构，比"用了什么库"更能说明工程能力。

## 四、PyTorch

- Tensor 与计算图：动态图意味着什么，它对调试和部署的影响分别是什么。
- 训练流程的四个要素：数据管道、损失、优化器、显存。
- 工程上真正常踩的：显存泄漏（图没断开）、忘记 `no_grad`、DataLoader 多进程问题、随机种子不可复现。
- 调优的第一步不是调超参，而是**先定位瓶颈**（数据、算力还是显存）。

## 五、Transformer

- 用工程语言解释 Self-Attention：它不是"算权重"，而是"信息路由"。
- 三个必答的"为什么"：为什么要除以 `√d`、为什么要多头、为什么需要位置编码。
- Encoder-only / Decoder-only / Encoder-Decoder 的取舍，落到"你的场景需要什么"。
- Masked Attention 在训练与推理中的角色不同，别混着讲。
- KV Cache：省了什么、代价是什么（显存换延迟）。
- 长上下文为什么难：注意力复杂度 + 训练成本 + 有效利用率的衰减。
- 为什么会"自信地胡说"：概率生成本质；工程上的解法是收窄自由度（RAG、约束输出、校验）。

## 六、多模态

- 多模态不是"文本模型加个图片编码器"，核心是**模态间的语义对齐**。
- 工程约束集中在三个地方：分辨率/帧率、长视频的 token 预算、模态缺失时的降级。
- 评估最难：跨模态任务没有单一指标，"好"要先定义清楚。

## 七、Agent 生态

- Agent = LLM + 工具 + 记忆 + 规划。**不是所有场景都适合做 Agent**。
- 一句话要能说清：Agent 是能力放大器，也是风险放大器。
- **LangChain**：Chain / Tool / Agent / Memory 的职责边界要分清。
- **LangGraph**：把 Agent 变成有状态的图，适合步骤明确、需要可控流程的场景。
- **LlamaIndex**：以数据与检索为中心，索引与查询的抽象更直接。
- **MCP**：工具与上下文的标准化协议；Server / Client 分工，Tool / Resource / Prompt 三类抽象，重点在权限与治理。
- **多智能体**：不是银弹。核心难点是分工边界、通信与上下文共享、冲突裁决、成本失控。
- 通用风险清单：无限循环、工具误调用、上下文膨胀、权限滥用。

## 八、部署

- 部署的不是"模型"，是**服务**：镜像、配置与密钥、健康检查、优雅退出、资源限额。
- 单机 / 多实例 / 多卡三种形态的差异主要在显存管理与并发模型。
- 必须设计四件事：超时、重试、降级、灰度与回滚。
- 为什么很多 Demo 上不了生产：没有并发设计、没有重试、没有配额、没有观测。

## 九、监控

- AI 监控 ≠ Web 监控：**要监控"效果"，不只是"可用"**。
- 四类核心信号：延迟、token 与成本、检索质量（RAG）、Agent 行为轨迹。
- 幻觉要可量化：异常输出率、兜底触发率、人工介入率、用户纠正率。
- 日志 / 指标 / Trace 分工清楚，并且提前设计告警分级，避免告警风暴。

## 十、HR 初筛

五个维度，每项 0–4 分，总分 24：

1. 岗位动机与角色认知
2. 项目真实性与参与深度
3. 是否理解 AI 是"系统工程"而非单点模型
4. 工程型岗位的成长潜力
5. 是否值得占用一次技术面名额

**风险信号**：只说"风口/好找工作"；把工作理解为"接个 API 写个聊天框"；排斥数据清洗、评估、上线后维护这类脏活。

## 十一、几条通用答题原则

- **先给结论，再给依据**——面试官的时间比你想的少。
- 讲**取舍**比讲方案值钱：为什么不用另一种，你在权衡什么。
- 每个技术点绑定一个真实场景，否则听起来像背的。
- 承认边界：做不到的说做不到，比硬编一个答案可信得多。
- 准备一个失败案例：原因、你做了什么、后来怎么改的。
